### **1. Key Stack and Queue Patterns**

#### **a) Stack: LIFO (Last In, First Out)**

A **stack** is a data structure that operates on a **LIFO** principle. The last element pushed onto the stack is the first to be popped.

* **Use Cases**:

  * **Expression evaluation** (e.g., for postfix expressions).
  * **Backtracking** (e.g., DFS traversal).
  * **Function call stack** (in recursion).

* **Operations**:

  * **Push**: Add an element to the top of the stack.
  * **Pop**: Remove the element from the top of the stack.
  * **Peek/Top**: Return the element at the top without removing it.
  * **IsEmpty**: Check if the stack is empty.

**Example Problems**:

* **Valid Parentheses** (LeetCode #20)
* **Evaluate Reverse Polish Notation** (LeetCode #150)
* **Min Stack** (LeetCode #155)

---

#### **b) Queue: FIFO (First In, First Out)**

A **queue** is a data structure that operates on a **FIFO** principle. The first element added to the queue is the first to be removed.

* **Use Cases**:

  * **Task scheduling** (e.g., managing job queues in operating systems).
  * **Breadth-First Search (BFS)** traversal.
  * **Order processing** (e.g., print queue).

* **Operations**:

  * **Enqueue**: Add an element to the end of the queue.
  * **Dequeue**: Remove the element from the front of the queue.
  * **Front**: Return the element at the front without removing it.
  * **IsEmpty**: Check if the queue is empty.

**Example Problems**:

* **Implement Queue using Stacks** (LeetCode #232)
* **Design Circular Queue** (LeetCode #622)
* **My Stack (using Queue)** (LeetCode #225)

### **2. Stack Algorithms & Patterns**

#### **a) Balanced Parentheses / Valid Parentheses**

This is a very common interview question where we use a **stack** to validate if the parentheses in a string are balanced.

* **How it works**:

  * Traverse the string character by character.
  * Push **open parentheses** onto the stack.
  * For **closing parentheses**, check if the top of the stack is the corresponding **open parenthesis**.
  * If it's a match, pop the stack. If there's no match, it's unbalanced.
  * At the end of the traversal, the stack should be empty for balanced parentheses.

* **LeetCode Problem**:

  * **Valid Parentheses** (LeetCode #20)

#### **b) Reverse a String / Reverse Words in a String**

You can use a stack to **reverse a string** or **reverse the words** in a string.

* **How it works**:

  * Push each character (or word) onto a stack.
  * Pop elements from the stack to reverse the order.

* **LeetCode Problem**:

  * **Reverse String** (LeetCode #344)
  * **Reverse Words in a String** (LeetCode #151)

#### **c) Next Greater Element**

This is a classic problem where we need to find the next greater element for each element in an array or a sequence.

* **How it works**:

  * Use a stack to keep track of the elements as we iterate through the array.
  * For each element, check if it's greater than the element at the top of the stack.
  * If it is, pop the stack and record the next greater element.
  * Continue this process for all elements.

* **LeetCode Problem**:

  * **Next Greater Element I** (LeetCode #496)
  * **Next Greater Element II** (LeetCode #503)

#### **d) Min Stack**

A **min stack** is a stack that supports retrieving the minimum element in constant time.

* **How it works**:

  * Use two stacks: one for storing the regular elements, and another to track the minimum element.
  * When pushing an element, if it's smaller than the current minimum, push it onto the min stack.
  * When popping, if the popped element is the current minimum, pop it from the min stack as well.

* **LeetCode Problem**:

  * **Min Stack** (LeetCode #155)

### **3. Queue Algorithms & Patterns**

#### **a) Implement Queue using Stacks**

This is a common interview problem where you are asked to implement a queue using two stacks.

* **How it works**:

  * Use two stacks: one for **enqueue** (adding elements) and the other for **dequeue** (removing elements).
  * When performing a **dequeue**, if the second stack is empty, transfer all elements from the first stack to the second stack, reversing the order.
  * This way, the first element of the first stack becomes the last element of the second stack.

* **LeetCode Problem**:

  * **Implement Queue using Stacks** (LeetCode #232)

#### **b) Implement Stack using Queues**

This problem asks you to implement a stack using two queues.

* **How it works**:

  * Use two queues: one for **push** operations and the other for **pop** operations.
  * When performing a **push**, add the element to the first queue.
  * When performing a **pop**, dequeue all elements from the first queue into the second queue, except the last one, which is the top element of the stack.

* **LeetCode Problem**:

  * **Implement Stack using Queues** (LeetCode #225)

#### **c) Circular Queue**

A circular queue is a queue in which the last element points to the first element, creating a loop.

* **How it works**:

  * Use a fixed-size array to represent the queue.
  * The **front** and **rear** pointers should wrap around to the beginning of the array once they reach the end.
  * This structure helps avoid wasting space by reusing empty slots.

* **LeetCode Problem**:

  * **Design Circular Queue** (LeetCode #622)

#### **d) Level Order Traversal (BFS)**

Queues are often used in **Breadth-First Search (BFS)** to traverse trees or graphs level by level.

* **How it works**:

  * Use a queue to store nodes at the current level.
  * For each node, dequeue it, process it, and enqueue its children (or adjacent nodes in a graph).

* **LeetCode Problem**:

  * **Binary Tree Level Order Traversal** (LeetCode #102)
